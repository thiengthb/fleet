- **Phase 1 quick fix (done, verified).** Copied 628's domain rows from the machine-A `.db` snapshot into this machine's live DB with a one-off `better-sqlite3` script, remapping `userId` source→local (raw same-schema copy = dates/FSRS verbatim; FK-checked; guarded; pre-backup at `~/Downloads/sakubun-live-before-restore.db`). Promoted local 628 → sole admin (861 demoted).
- **Phase 2 durable fix (done, committed `2cd548e`).** `importSystemBackup` now reconciles users by email + translates every user FK (userId AND authorId, via `foreign_key_list`) through a `uidmap`, merging with `INSERT OR IGNORE`. `ADMIN_EMAIL` → admin on create on any machine. 228 tests pass, lint+build green, integration-verified on a copy of the live DB against the crashing snapshot (no crash, data preserved).
- **Gotcha caught by running it:** targetless `ON CONFLICT DO NOTHING` is a syntax error on the driver-adapter's SQLite → used `INSERT OR IGNORE`. Unit tests + build did NOT catch this; the integration run did.

**Decisions made** — `sakubun/docs/decisions.md` 2026-07-24 "Cross-machine sync collides on user.email" (root cause + Phase 1 + Phase 2 + INSERT OR IGNORE gotcha + better-sqlite3 date trap).
