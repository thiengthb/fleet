**What happened**

- User asked whether the "add vocab to Anki" feature still works on this deploy. Verified empirically
  (not reasoned): container is up, `host.docker.internal` resolves, but port 8765 refuses — Anki was
  installed on the host, AnkiConnect installed, `webBindAddress` was `127.0.0.1`, Anki was closed. So
  the LOCAL path was one config + open-Anki away from working.
- The real question the user then asked: does it work for OTHER accounts hitting the site from THEIR
  machines? No — a server-side push reaches only the container HOST's Anki, never a remote member's
  `localhost`. That is a by-construction break for a multi-user deploy, not a setup issue.
- Chosen fix (user picked): DELETE the AnkiConnect push, replace with a downloadable `.apkg` the member
  imports into their own Anki. Removed `lib/anki.ts` + the `add_vocab_to_anki` MCP tool + compose
  `extra_hosts`; added `lib/anki-apkg.ts` (builds the deck by hand with better-sqlite3 + fflate — no
  sql.js), `app/api/export/anki/route.ts`, and a "Tải bộ thẻ Anki" button in Settings → Dữ liệu.
- Vocab already lives in sakubun (`Item` kind=VOCAB) so no new model, no migration — the export is a
  scoped read + format, reusing `buildBack`. Note guids derive from the Item id so re-export UPDATES
  instead of duplicating; cards export as NEW (FSRS state deliberately not carried).
- Verified against a READ-ONLY copy of the prod DB (deleted after): 4 accounts, each got only their own
  words (2/1/0/0), no duplicate guids, cards render furigana · Hán Việt · nghĩa · ví dụ. The `req` key
  in the note-type JSON is load-bearing — without it Anki imports the notes but generates ZERO cards; a
  test asserts it. Container rebuilt (healthy, /api/export/anki → 401 unauthenticated).

**Decisions made** — `sakubun/docs/decisions.md` 2026-07-23 "Anki export: AnkiConnect push replaced by
a downloadable .apkg"; closed `docs/plans/2026-07-11-anki-vocab-push.md` (status carried a `removed:`
line pointing at that decision). Cross-project line in `06-knowledge-ledger.md` §A.
