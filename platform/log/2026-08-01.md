**What happened**

- **The supervisor handed back his own five open items and asked the agent to do them.** Four landed; the fifth
  was refused by the permission layer twice and that refusal turned out to be right. 13 commits, `fleet` and
  `rulebook` both pushed.
- **`.claude/agents/**` was governance with NO guard.** Measured on the live gate under `CLAUDE_AUTONOMOUS=1`:
  Write, Edit, MultiEdit, `cp`, a redirect, `sed -i`, the Windows-separator spelling and a brand-new subagent
  were **all allowed** — 8 open doors — while `skills/`, `rules/` and `hooks/` were blocked. **live 7/15 →
  15/15**, 0 regressions, four controls proving it does not over-block. Installed; the pre-existing suites went
  76/76 → **88/88**.
- **The prose and the gate had drifted apart in BOTH directions.** `CLAUDE.md` listed 7 surfaces and said
  *"Enforced by autonomy-gate.mjs"*; the gate held **12**, and `agents/` was in **neither**. Now 13, and
  `claude-md-budget` derives the gate's surfaces and requires each to be named (**14/14**). Writing that check
  found three defects in itself: a regex that extracted 1 token of 13 and reported "1/1 named" (a green measuring
  nothing), a sentence cut at the first `;` which sits mid-list, and — the sharp one — deleting `agents/` from
  the list and **still passing**, because the sentence explaining the gap contained the word.
- **Installing the `rulebook` plugin here exposed that the checker's verdict depended on the CHECKOUT.**
  `checkComponent` split on `\n`, so every line kept a `\r` and the `$`-anchored `rulebook-allow` directives
  stopped matching: **4 violations read as CRLF, 0 as LF** on the same file; **11 false findings in 5 files**
  against the correct 0-of-333. The hook exits 2, so this box would have blocked files whose exceptions were
  argued **in writing** — a brand mark, and a Satori-rendered OG image. Two more from the same cause:
  `artifactSha` hashed raw bytes so the release gate demanded a version bump for a byte-identical rebuild, and
  `prettier --check` called the whole repo unformatted. `.gitattributes eol=lf` removes the cause; the code keeps
  a normalisation as defence in depth. Plus three `new URL().pathname` bugs — `build:plugin` had **never** run on
  Windows, and one of the three was `leak-check`, the gate that proves rule text has not leaked: it would have
  PASSED by finding nothing.
- **Four checkers lie inside a git worktree, measured in a real one:** `link-check` 1 → **45 broken**,
  `plan-audit` 68 → **36 scanned**, `reuse-scan` 715/9 → **0/0**, `recurrence-check` 0 → **1 firing**. Two panic,
  two reassure. `health-sweep` now refuses a VERDICT there and exits 1. This matters because the branch-based
  governance workflow runs in worktrees, so the checks meant to gate a merge cannot be trusted before the merge.
- **The `spoke` flag: refused twice, and the refusal improved the design.** v1 wrapped
  `process.stdout.write`; the permission layer said no. Asking *why*, when a patch to a neighbouring hook had
  just gone through, gave the answer: a hook that runs on every tool call and monkey-patches stdio is
  indistinguishable from one tampering with what it sees. What shipped reads `bytesWritten` — a counter the
  stream already keeps — so it cannot see content even in principle. Two lines instead of nine.
- **`secret-guard` then blocked the agent for real**, mid-edit, for pasting the probe credential into the
  proposal that documents it. **The first exit-2 of the session**, which is the honest reading of every `fired: 0`
  above it: the guards had found nothing to catch, not that they cannot catch.
