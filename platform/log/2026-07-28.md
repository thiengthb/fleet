Two inversions worth remembering past the detail.

**① Build ON the harness, not BESIDE it.** Auto-pilot was competent work on an expired premise: nothing in the process
was wrong — research-before-design ran, the gate was exhaustively tested, propose-don't-execute held — but no step ever
re-checked whether the capability had arrived from the platform. It had. The same day, memory moved onto native rails
and *gained* enforcement we had never managed to impose ourselves. The highest-value source in a 40-source research
pass turned out to be the official docs of the tool the agent runs inside. `harness-drift-check` exists so the next one
is found by measurement rather than by noticing.

**② Restructure, don't restate — and now we can prove it.** The ledger rule was written down on 2026-06-12 and violated
203 times. What fixed it was not saying it louder but making the compliant path the obvious one. Measured, 3 runs × 4
cells, one variable: control rows 340–738 chars with the reasoning pasted in, every trial; treatment 156–199 with a
separate anchored entry, every trial. **This is the first claim this platform has backed with measurement instead of
argument** — and the measurement immediately earned its keep by exposing two defects in its own harness (a fixture leak
and a false negative) before the result was believed. Escalation order is now: structure → measure → gate.

The residue is honest: the platform's disease was never "too weak", it was **too much machinery per unit of shipped
value**. This session removed more than it added — ~6 sessions of orchestrator, 120 lines of crypto in the gate, 5
plans, one 421KB file — and the parts that stayed got smaller and better tested.
